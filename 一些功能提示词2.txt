原始的引用的设计逻辑：
1、读取、打开文档时，保存文档的原始路径信息。这个信息可以在保存时使用。鼠标放到已打开的文档时，会悬浮展示。
2、嵌入媒体，嵌入引用时，要写入真实路径，例如udd.media/media_0.jpg，读取时，也读取实际的路径。不要读浏览器的缓存。  =测试文档1.t1-1，也写为真实的=udd.ref-docs....。udd表示引用的内容在本文档中。
3、引用和媒体，可选来源。例如来自udd文件中嵌入的内容，2、仓库的内容。提供嵌入内容来源选择功能按钮。按钮放在“渲染”的旁边。



`=t1-1`                        │ 整节点引用（本文档） │ 克隆整个节点含子节点
   `=t1-1.content`                │ 字段引用（本文档）   │ 取节点的某个字段值
   `{{=t1-1.content}}`            │ 内联引用             │ 混在文字中间
   `=测试文档1.t1-1`              │ 跨文档引用           │ 引用另一个 .udd 文件
   `=udd.ref-docs.测试文档1.t1-1` │ 嵌入跨文档引用       │ 从 .udd 内嵌数据读取
   `=Sheet1.B2`                   │ 表格引用             │ 引用 xlsx 单元格
   `{{Sheet1.A1:C4}}`             │ 内联表格             │ 渲染为 HTML 表格
   `{{"image":"xxx"}}`            │ 媒体标签             │ 图片/视频/音频

引用内容的获取，只能来自两个函数：  
函数1：整个节点的引用，不带{{...}}：使用=t1-1，=udd.ref-docs.测试文档1.t1-1、=测试文档1.t1-1。
函数2：非整个节点的引用，都带{{...}}：{{=t1-1.content}}、{{Sheet1.A1:C4}}、{{Sheet1.A1:C4}}、{{"image":"xxx"}}等。
引用内容查找逻辑顺序：
	1、本文档（不要读取浏览器缓存，直接读取实际路径，例如udd.ref-docs压缩包内，udd.media/media_0等实际路径）
	2、仓库（不要读取缓存，直接读取实际路径）
	3、本机的实际路径，例如\"D:\\\\cym\\\\屏幕录制 2026-04-05 195107.mp4\
所有内容，严格按照以上顺序查找，禁止读取浏览器缓存。
引用完成后，使用当前已有的函数，进行正常的渲染。

完全理解以下思路后，进行重构。
还是有的时候，多媒体会渲染失败。注意本文档的设计逻辑：原始数据--多种渲染。不管是什么页面，只是展示的方式不同，不存在复杂的逻辑，都使用最简单的渲染逻辑。 
渲染逻辑：直接读取对应的原始数据，包括各种媒体等，遇到“=”或“{{...}}”时深入其中，读取到原始数据，再进行下一步的渲染。
例如：
{
  "t1-1": {
    "content": "源数据：HelloWorld 2026",
    "hide": 0,
    "hide_body": 0,
    "t2-1": {
      "content": "标题1-1",
      "hide": 0,
      "hide_body": 0
    },
    "t2-2": {
      "content": "插入视频{{\"video\":\"D:\\\\cym\\\\屏幕录制 2026-04-05 195107.mp4\",\"video.width\":\"100%\"}}",
      "hide": 0,
      "hide_body": 0
    },
    "t2-3": {
      "content": "插入图片{{\"image\":\"D:\\\\cym\\\\Snipaste_2026-04-05_19-58-14.png\",\"image.width\":\"100%\"}}",
      "hide": 0,
      "hide_body": 0
    },
    "body": "标题1的正文"
  }
}

那就按顺序展示： 源数据：HelloWorld 2026  标题1-1  插入视频，此时遇到{{\"video，那就去寻找源文件，读取回来之后，再进行渲染。 
然后又遇到了{{\"image，那么就有去找到原始数据，然后回头进行渲染。
原始内容在哪里，非常容易分辨，D:\之类的，肯定是本地路径
测试文档1.之类，肯定是仓库
udd.肯定是本文件嵌入的内容。
=t 这类，肯定是本文件。
遇到冲突时，就按照本文件，仓库，本机路径的顺序进行读取。通常不可能遇到冲突。
任何时候，都不要读取不可靠的缓存。

{
  "t2-2": {
    "content": "表格{{Sheet1.A1:C4}}",
    "hide": 0,
    "hide_body": 0
  }
}
遇到Sheet，就去读取表格，严格限制，表格必须Sheet开头。

何时刷新渲染内容的来源？鼠标双击，打开查看原始内容时，然后又关闭时，仅刷新刚刚打开和关闭的部分，其他位置均不做刷新。单击"渲染 on"、"渲染 off"时，仅改变渲染方式。
以上提到的渲染方式，适用于：大纲、思维导图、文档、表格、演示，所有场景。
按照这样的逻辑，应该不会有渲染失败的情况。理解设计思路，进行重构。
