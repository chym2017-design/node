# 2026-05-08 单 HTML 打包与混淆方案

## 一、目标

把 UDD（`udd-app.html` + 16 个 JS + 3 个 CSS + `server.js`）打成**一个 HTML 文件**，同时满足：
- 双击即用，或托管静态站即用（不依赖 `server.js`）
- 核心算法（`udd-data.js` / `udd-ref.js` / `udd-mindmap.js`）做**重度混淆**，抬高同行复用门槛
- 性能不降级（反而希望比原版更快）
- 六视图（大纲 / 思维导图 / 文档 / 表格 / 图谱 / 演示）全部功能等价

## 二、最终架构

### 构建流水线（build.js）

```
读取 udd-app.html
  ├─ 解析 <link rel=stylesheet> → 内联为 <style>
  └─ 解析 <script src> 顺序
      ├─ vendor (*.min.js)                 → 透传
      ├─ own JS（terser 模式）              → terser 压缩
      └─ core JS（OBFUSCATE=1）            → terser + obfuscator + IIFE 包裹 + window expose
输出 → dist/udd-app.standalone.html   (~1.5 MB，单文件)
     + dist/manifest.txt              (行号 → 源文件映射，调试用)
```

三个运行模式：

| 环境变量 | 行为 | 用途 |
|---|---|---|
| 不设 | 仅 terser，所有 own 文件只压缩 | 开发迭代 |
| `OBFUSCATE=1` | 三个 core 文件加重度混淆 | 发布 |
| `OBFUSCATE=udd-data` / `udd-ref` / `udd-mindmap` | 单文件 bisect | 排查"某文件混淆挂了" |
| `RAW=1` | 什么都不做，原样合并 | 最底层验证（合并本身是否正确） |

$env:OBFUSCATE='1'; node build.js

### 分层防护强度

| 文件 | 处理 | 防护强度 |
|---|---|---|
| `jszip.min.js` / `markdown-it.min.js` / `xlsx.min.js` / `pptxgen.min.js` | 透传 | 0（本就是 vendor） |
| `udd-app.js` / `udd-outline.js` / `udd-document.js` / `udd-sheet.js` / `udd-ppt.js` / `udd-graph.js` / `udd-media.js` / `udd-file.js` / `udd-mdhtml.js` | terser 压缩（`mangle.toplevel: false`） | ★ |
| `udd-data.js` / `udd-ref.js` / `udd-mindmap.js` | terser → obfuscator → IIFE 包裹 | ★★★★ |

obfuscator 配置要点：
- `controlFlowFlattening: true` (threshold 0.5) — 主力
- `stringArray + RC4` (threshold 0.7) — 主力
- `identifierNamesGenerator: 'mangled-shuffled'` — 标识符 mangle
- `renameGlobals: false` + 自动提取的 RESERVED 列表 — 保留用户定义的顶层名
- `transformObjectKeys: false` — 必须关，否则暴露给外部的常量对象（`ESCAPE_TABLE`）key 被重命名
- `numbersToExpressions: false` — 关，避免 typed-array / 二进制路径边界问题
- `splitStrings: false` — 关，观测到偶发问题
- `deadCodeInjection: false` — 性能杀手 / 防护废物比最高的开关，当前关闭
- `selfDefending: false` / `debugProtection: false` — 5–10% 用户兼容性事故率，不开
- `seed: hashSeed(file)` — 每文件不同，配合 IIFE 双保险避免跨文件 var 撞名

### IIFE 隔离（关键结构）

每个混淆文件的输出结构：

```js
(function(){
  /* obfuscator 生成的 var _0xXXXX = [...]、var _0xYYY = decoder(), 
     用户定义的 function debounce / deepClone / class MindmapView ... */
  ;Object.assign(typeof window!=='undefined'?window:globalThis,{
    debounce, deepClone, ESCAPE_TABLE, MindmapView, /* 等用户级顶层名 */
  });
})();
```

**没有 IIFE 时的灾难**：obfuscator 的 `var _0xabc = [...]`（stringArray）直接挂 window，多个混淆文件的短名有概率撞车，后加载文件覆盖前一个，导致前一个文件运行时解码到错的字符串 → "X.get is not a function" 等怪异报错。

### 性能优化（udd-ref.js + udd-data.js）

为了吸收混淆带来的固定常数倍开销，对引用解析热路径做了四层缓存：

1. **parseRef 全局 memo**（`_parseRefCache = new Map`）— 纯函数，永久缓存
2. **`.udd.` indexOf 快路径** — 同档引用跳过 split + for 循环扫描 `udd` 段
3. **`refreshRefs` 单 pass cache** — 同次 refresh 内同 refStr 只解析一次
4. **`_pathIndex` 路径索引** — 一次性扫树建 `tNodeKey → fullPath` 字典（`Object.create(null)`，不用 Map 避免 `.get`/`.has` 方法名被 stringArray 编码），`findRefNode` / `findFullPath` 从 O(N) DFS 兜底变 O(1) 属性查找

路径索引在 `indentNodeData` / `outdentNodeData` / `moveNodeData` 末尾置 null 失效，下次访问 lazy 重建。

## 三、踩过的 5 个大坑

### 坑 1：`String.prototype.replace` 的 `$\`` 通配符吃掉源码

**现象**：`udd-app.standalone.html` 的 1230 行突然冒出 `<!DOCTYPE html>`，混在 JS 代码里。

**根因**：`outHtml.replace('</body>', \`${bundleJs}\n</body>\`)` 把 `bundleJs` 当字符串塞进替换。`bundleJs` 里 `udd-data.js` 第 304 行的 `new RegExp(\`^t${level}-\\d+$\`)` 含 `$\`` 序列——`replace` 的字符串替换模式把 `$\`` 解释成"匹配项前的整段输入"，整段 HTML head 被插进 JS 中间。

**修法**：`replace('</body>', () => \`${bundleJs}\n</body>\`)` 用函数回调。函数返回值不走 `$` 特殊解释。

### 坑 2：跨文件 `var _0xXXXX` 撞名

**现象**：`TypeError: /^t\d+-\d+$/[iV(...)] is not a function`——regex.test 被 obfuscator 重写为 `regex[decoder('test')](key)`，但 `decoder` 被另一个文件的同名 var 覆盖了。

**根因**：obfuscator 默认把 stringArray 和解码器作为顶层 `var` 输出到当前脚本。多个混淆文件在 window 作用域的短名有概率撞车。

**修法**：每个混淆文件包进 `(function(){ ... })()` IIFE，内部 var 不污染 window。用户定义的顶层符号通过 `Object.assign(window, {...})` 显式 expose。

### 坑 3：自动 reserved 抓到函数体内的局部变量

**现象**：`Uncaught ReferenceError: num is not defined`——IIFE 的 expose 列表里出现了 `num`、`c`、`nx` 这种看起来像混淆名的东西，但其实是源码里函数体内的局部变量被错误识别为顶层。

**根因**：提取正则用了 `^\s*(function|const|let|var)...`，`\s*` 允许前导空白，把 `  const num = ...`（函数体内 2 空格缩进）识别为顶层。

**修法**：把正则改为严格列 0 起始 `^function\s+...` / `^class\s+...` / `^(const|let|var)\s+...`。后来又发现 `async function` 和 `function*` 也要覆盖，统一为 `^(?:async\s+)?function\s*\*?\s*NAME`。

### 坑 4：Map 方法名被 stringArray 编码错位

**现象**：`TypeError: O.get is not a function`——`_pathIndex.get(key)` 在混淆后失败。

**根因**：`.get` / `.set` / `.has` 是字符串字面量形式的方法名，obfuscator 的 stringArray 把它们加密，跨 IIFE 调用时解码器 resolve 错。

**修法**：`buildPathIndex` 改用 `Object.create(null)` 返回普通字典对象；`findRefNode` / `findFullPath` 全部用属性访问 `idx[key]` 替代 `.get(key)`。简单属性访问没有方法名字符串要编码。

### 坑 5：`async function` / `function*` 没被自动 reserved 识别

**现象**：PPT 视图空白，`ReferenceError: resolveRefAsync is not defined`。

**根因**：`async function resolveRefAsync(...)` 起始是 `async `，我的顶层提取正则 `^function\s+NAME` 匹配不到。于是 `resolveRefAsync` 没加进 RESERVED，没进 IIFE expose 列表，挂不到 window 上。

**修法**：提取正则扩展为 `^(?:async\s+)?function\s*\*?\s*NAME`，同时覆盖 async 和 generator。
