# UDD 项目 · 协作者上手指南

> 欢迎参与 UDD（统一数据展示系统）的开发！
> 本指南带你完成从拉取代码到提交贡献的完整流程，约 10 分钟。

---

## 一、协作规则（先说清楚）

| 分支 | 权限 | 用途 |
|------|------|------|
| `main` | 🔒 受保护，**不能**直接推送 | 稳定版本，由仓库主控制 |
| `dev` | ✅ 你可以自由拉取和推送 | 日常开发分支 |

你的工作流永远是：**在 `dev` 上开发 → 推送到 `dev` → 提 PR 申请合并到 `main` → 仓库主审批合并**。

直接 push 到 `main` 会被 GitHub 拒绝，这是正常现象，不是你操作错了。

---

## 二、第一次：拉取代码

```bash
# 1. 克隆仓库
git clone https://github.com/chym2017-design/node.git
cd node

# 2. 切换到 dev 分支（这是你以后的工作分支）
git checkout dev

# 3. 安装依赖（仅构建时需要，纯使用/改文档不需要）
npm install

# 4. 本地运行
node server.js
# 然后浏览器打开 http://localhost:8080
```

> 如果 clone 时提示无权限，请联系仓库主在
> Settings → Collaborators 中添加你的 GitHub 账号。

## 三、日常开发流程

### 1. 开始干活前，先拉最新代码

```bash
git checkout dev
git pull
```

⚠️ **每次动手前都先 pull**，这是避免冲突最重要的一步。

### 2. 修改代码

- 源码在 `js/`、`css/` 目录，`udd-app.html` 是主入口；
- 脚本加载顺序和文件职责说明见根目录 `readme.txt`；
- 功能设计细节见 `功能设计文档（完整版）2.md`。

### 3. 提交并推送

```bash
git add -A
git commit -m "简述你的改动，例如：修复表格引用不更新的问题"
git push
```

提交信息请写清楚"做了什么"，一行说完，例如：

- ✅ `修复大纲视图拖拽后层级错乱`
- ✅ `新增思维导图导出 SVG 功能`
- ❌ `更新`、`修改`、`fix`（太模糊）

### 4. 本地构建（改了源码需要验证打包时）

```bash
npm run build
# 产物在 dist/udd-app.html
```

## 四、把改动合并到 main（提 PR）

当你的功能在 `dev` 上完成并测试通过后：

1. 打开 `https://github.com/chym2017-design/node/pulls`
2. 点 **New pull request**
3. 设置 **base: `main`** ← **compare: `dev`**
4. 标题写清楚本次合并包含什么，点 **Create pull request**
5. 通知仓库主审批，审批通过后由仓库主合并

> PR 没通过前，你的改动只存在于 `dev`，不影响 `main` 的稳定版本，
> 所以放心推送，不用有心理负担。

## 五、常见问题

**Q1：我不小心在 main 上改了代码怎么办？**

```bash
# 还没提交：把改动转移到 dev
git stash
git checkout dev
git stash pop
```

**Q2：push 时报错 "Changes must be made through a pull request"？**

你正在往 `main` 推。执行 `git checkout dev` 切回开发分支再推。

**Q3：pull 时提示冲突（conflict）？**

```bash
# 先把自己的改动暂存
git stash
git pull
git stash pop
# 然后按提示打开冲突文件，手动解决 <<<<<<< 标记处
```

实在搞不定时，**不要**强行操作，把报错截图发给仓库主。

**Q4：能新建自己的分支吗？**

可以。功能较大时建议从 `dev` 拉功能分支：

```bash
git checkout -b feature/你的功能名 dev
# 开发完成后推送到远端，再合并回 dev
```
