# 2026-04-24 引用与媒体渲染重构

本次更新围绕"原始数据 → 多种渲染"的统一渲染哲学，把原先散在大纲 / 文档 /
演示各视图里的引用解析和媒体采集逻辑收敛到一套公共底座，并修掉若干破坏性 Bug。

## 一、设计原则（本次重构沿用，后续改动须遵循）

1. **一份原始数据，多种展示**。引用与媒体的解析策略由公共底座统一负责，各视图
   只决定"把解析结果画成什么样"。
2. **读取优先级固定**，与运行环境（是否启动 `server.js`）无关：
   1. 本文档（含 `udd.ref-docs.*` 嵌入）
   2. 仓库
   3. 本机绝对路径
   是否开 server 只影响其中**某些候选能否成功读取**，不改变顺序和逻辑分支。
3. **禁止读取浏览器缓存**，所有解析直接命中原始路径。
4. **节点原始数据（`node.content` / `node.body`）是唯一真源**。任何渲染视图都
   不得在 contentEditable 的副作用中把解析后的中间文本写回原值。

## 二、修改清单

### 1. 公共引用解析底座（`js/udd-ref.js`）

#### 1.1 `isRef` 严格化

原判定仅检查 `startsWith('=') && length > 1`，会把尾部带空白、IME 零宽字符或
换行的脏字符串误判为引用，导致 `parseRef` 找不到节点进而渲染出 `#REF!` /
`#LOADING...`。

新判定要求：
- 首字符必须是 `=`；
- 第 2 个字符必须是合法标识符首字符（ASCII 字母 / 数字 / 下划线 / 中文）；
- 结构必须能通过内联 SheetRef 正则或 `parseRef` 解出 `nodePath`。

内联 SheetRef 判定逻辑直接写在 `isRef` 内部，避免和 `isSheetRef` 形成互相递归
（之前因 `isSheetRef` 第一行调 `isRef`、`isRef` 又调 `isSheetRef` 导致栈溢出
页面全白，已修复）。

#### 1.2 统一的媒体项收集器

新增两个公共函数：

```js
collectMediaItemsFromText(data, text, visited?)         // 同步
collectMediaItemsFromTextAsync(data, text, visited?)    // 异步（支持跨文档懒加载）
```

语义：扫描一段文本，按出现顺序产出 mediaItems（`image` / `video` / `audio` /
`table`）。处理规则：

| 输入片段 | 行为 |
|---|---|
| 整段 `=ref`（无 `{{}}`） | 深入源节点的 `content` + `body`，递归收集 |
| `{{=ref}}`（内联） | 解析 ref，对结果再递归收集 |
| `{{"image":...}}` / `{{"video":...}}` / `{{"audio":...}}` | 产出对应 mediaItem |
| `{{Sheet1.A1:C4}}` | 产出 `{type:'table', tableRef}` |

`visited` 集合用于防止环形引用死循环。async 版本在同步命中失败时会调
`resolveRefAsync` 触发跨文档 / 嵌入文件的懒加载后再重试。

---

### 2. 媒体渲染统一入口（`js/udd-media.js`）

#### 2.1 `renderTextWithMedia` 改造

内部不再自行扫 `{{...}}`，而是调用 `collectMediaItemsFromText` 得到 mediaItems
后统一绘制。好处：任何"某个文本里藏着 `=ref` 链 / `{{=ref}}` 嵌套媒体"的场景都
能被深入展开。outline / document 的媒体区调用**直接传 `node.content` / `node.body`
的 raw 原始值**，不再传解析后的 `displayContent`（这样链式引用里的媒体也能拉到）。

#### 2.2 新增 `_bindMediaSrcWithFallback(el, src)`

为 `<img>` / `<video>` / `<audio>` 绑定 src，失败自动按候选列表顺序回退。这是
"读取优先级固定、与 server 解耦"原则在 DOM 层的体现。

---

### 3. 媒体路径候选化（`js/udd-app.js`）

新增 `resolveMediaSrcCandidates(src)`，按固定顺序返回候选 URL 数组：

| src 形态 | 候选顺序 |
|---|---|
| `http://` / `https://` / `data:` / `blob:` | 原样（一个候选） |
| `udd.media/xxx` | ① `session.embeddedMedia` blob → ② server 提取 zip entry |
| `D:\xxx`（本机绝对路径） | ① server 代理 → ② 原样兜底 |
| 其它 | 原样 |

`resolveMediaSrc(src)` 退化为"取首选"。

**关键点**：这个列表的顺序与"是否开 server"**完全解耦**。开 server 只是让后面
的仓库 / 本机候选能访问成功；关 server 时这两个候选被尝试但会失败，`onerror`
自动滑到下一个。因此读取**逻辑和优先级永远不变**。

---

### 4. 演示（PPT）视图用同一套（`js/udd-ppt.js`）

这次重构真正把 PPT 对齐到其它视图：

#### 4.1 `_collectMediaItems` → `_collectMediaAsync`

封装成 async 方法，内部直接调公共 `collectMediaItemsFromTextAsync`。过去 PPT 的
`_collectMediaItems` 只在 raw 文本上用正则跑，**永远不会深入 `{{=ref}}` 或 `=ref`
里的媒体**——这是"演示里引用的视频不展示"的根因。

#### 4.2 主节点自身媒体补齐

`_buildContentSlide` / `_buildSplitSlides`：
- 现在会扫描**主节点自己的 `content` 和 `body`**（原来只扫 body）；
- full-ref fallback 分支（主节点 content 是 `=t1-1` 且无子节点）会扫描**源节点自己
  的 `content` 和 `body`**（原来只扫源节点的 children）。

#### 4.3 渲染层候选绑定

`_renderSlideHTML` 里 `<img>` / `<video>` / `<audio>` 不再直接写 `src`，改成
`data-mediasrc="原始路径"` 占位。`_renderUI` 在 `innerHTML` 赋值后调
`_bindMediaElements(rootEl)`，通过公共 `_bindMediaSrcWithFallback` 绑定候选数组
+ `onerror` 回退。

> 结果：PPT 的视频 / 图片和大纲 / 文档走的是同一条路径，优先级也一致。

### 5. 编辑 contentEditable 的反污染（`js/udd-outline.js` / `js/udd-document.js`）

这是修掉"双击 `{{=ref}}` → 再点出去 → 节点末尾冒出 `{{{{{{` / 卡在编辑态"的关键。

#### 5.1 根因

- contentEditable 在编辑期间的 `el.textContent` 不是稳定的输入：选区恢复、IME、
  Enter、`renderStyledText` 把内容拆成 `<span>` 等都会让读到的字符串和原值有
  细微差异（零宽字符、换行、空白等）。
- 原 `onInput` / `syncAll` 一看到差异就写回，并且 `mergeEditableTextAndMedia`
  会把原始 media tag 保留再拼接——差异一旦出现，每次事件都拼接一份，形成
  `{{{{{{` 累积。
- 原 `onFocusOut` 只判 `isRef(val)`，含 `{{=ref}}` 的节点失焦不重渲，视觉上卡住。

#### 5.2 修复方案：显式"编辑原始态"标记

引入 `data-ref-editing=<原始字符串>` 数据属性：

1. **`onRefDblClick` 进入编辑原始态时**：把 `node[field]` 的原始值写入
   `refEl.dataset.refEditing`，同时设 `contentEditable=plaintext-only` 并显示原始
   字符串。
2. **期间所有写回全部跳过**：`onInput` 和 `syncAll` 只要看到 `dataset.refEditing`
   存在就直接 return，绝不碰 `node`。
3. **`onFocusOut` 集中结算**：对原始值与当前 `el.textContent` 做"去白 + 去零宽"
   规整化比较：
   - 完全一致：什么都不动，直接重渲（恢复 ref 解析显示）。
   - 真有变化：按 `node[field] = edited` 字面赋值（**不走 `mergeEditableTextAndMedia`
     的拼接**，避免再次产生 `{{` 重复）。
   - 清掉 `data-ref-editing`，重渲。
4. **`onFocusOut` 的常规分支**也扩展了：除 `isRef(val)` 外加 `hasInlineRefs(val)`
   判定，保证含 `{{=ref}}` 的节点失焦都会重渲恢复。

#### 5.3 额外的 onInput 保护

对原值是 `isRef` 或 `hasInlineRefs` 的节点，onInput 先做"去白 + 去零宽"规整化
比较；规整后一致就当无改动，直接 return。这层是二级防线，防止以后不走
dblclick 路径的场景也可能出现类似污染。

## 三、验证清单

不启动 `server.js` 的场景（`.udd` 直接打开）：

1. 打开含嵌入媒体 + 引用的 `.udd`，大纲 / 文档 / 演示视频图片都能正常显示。
2. 双击引用节点 → 原始 `{{=…}}` / `=…` 可见；点外面 → 立刻恢复解析渲染；数据
   里 `node.content` / `node.body` 和原文保持一致，不出现多余字符。
3. 演示页，含 `=t1-1` 或 `{{=t1-1.content}}` 的节点，被引用节点里藏的视频、
   图片都能出现在对应 slide。

启动 `server.js` 并从仓库面板打开同文件：

1. 现象应与不开 server 完全一致；
2. 断网 / 停 server 时媒体能自动回退到嵌入 blob（前提：打开时已解包嵌入媒体）。

## 四、后续建议（未做，仅记录）

- `mergeEditableTextAndMedia` 目前靠"删除原始 media tag + 重新拼接"实现正文
  和媒体的并存。这种拼接在异常 contentEditable 输入下容易重复。未来可以改成
  "media tag 不落在可编辑文本里，完全由单独 DOM 层维护"，彻底去掉拼接。
- "来源按钮"（嵌入 / 仓库 切换）当前 UI 上存在但 `resolveMediaSrcCandidates`
  还没把 `contentSource` 纳入顺序控制。若业务需要用户强制某个来源，可在候选
  生成时按 `contentSource` 过滤。
- 跨文档引用的 `_loadDocFromServer` 只在开 server 时有效；后续可以把"从同目录
  下其它 `.udd` 读取"做成预加载到 `_refDocCache` 的后台任务。
